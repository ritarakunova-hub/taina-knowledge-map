# TAINA Knowledge Map V1

### Защита сохранения и экспорта

- Запись проекта и активного указателя выполняется одной транзакцией IndexedDB; сохранение использует неизменяемый снимок состояния.
- При открытии локальная запись проверяется без предварительного заполнения отсутствующих полей значениями по умолчанию. Если структура не проходит проверку, приложение не включает автосохранение поверх неё.
- CSV нейтрализует значения, которые табличные редакторы могут принять за формулы. XLSX записывает пользовательские значения как inline strings и очищает недопустимые XML control characters.


## Маршрут пользователя в приложении

В интерфейсе есть семишаговый маршрут первого пилота. Его прогресс вычисляется по данным проекта, а не по календарным датам; ориентир — 5–7 часов активной работы для небольшого пилота. Подробные критерии каждого шага находятся в `materials/05-in-app-journey.md`.

## Визуальная система TAINA

Интерфейс использует фирменную палитру: глубокий чёрно-сливовый фон (`#171314`), тёплое золото (`#D2B878`), винный (`#6C303D`), пыльную розу (`#B98C91`) и мягкие графитово-сливовые поверхности. Ромб в знаке TAINA — небольшой фирменный акцент. Контраст и сдержанная типографика сохранены ради удобства ежедневной работы, а не декоративности.


Local-first веб-приложение для руководителя: собрать корпоративные источники знаний, связать их с процессами, зафиксировать пробелы, проверить ответы AI по первоисточникам и спланировать обновление.

## Запуск на Windows

1. Установите Node.js 22.6.0 или новее (рекомендуется актуальная LTS-версия).
2. Откройте PowerShell в этой папке (Shift + правый клик → «Открыть окно PowerShell здесь»).
3. Выполните:

```powershell
npm install
npm run dev
```

4. Откройте **точный адрес**, который напечатает Vite в PowerShell (при привязке к `127.0.0.1` это обычно `http://127.0.0.1:5173`). Не заменяйте `127.0.0.1` на `localhost` и не переключайтесь между адресами: браузер считает их разными источниками (origins), поэтому у каждого будет отдельная база IndexedDB и проект может выглядеть пропавшим. Не закрывайте окно PowerShell, пока пользуетесь приложением.

Для остановки нажмите `Ctrl + C` в PowerShell.

## Основной сценарий

1. **Моя компания** — заполните базовую карточку и при желании диагностику.
2. **Ответственные** — добавьте владельцев процессов и источников.
3. **Процессы** — опишите цель, шаги, входы, результат и владельца.
4. **Источники** — внесите документы, системы и знания сотрудников; укажите расположение, процесс и владельца.
5. **Документы** — зафиксируйте версии, статус и следующую дату проверки.
6. **Проблемы и пробелы** — записывайте противоречия, отсутствующие инструкции и зависимости от устных знаний.
7. **Проверка AI-готовности** — создавайте вопросы, ожидаемые ответы и связывайте их с источниками. Итоговый статус выставляет человек.
8. **План развития** — превратите найденные проблемы в задачи с владельцами, сроками и этапами.
9. **Качество карты** — используйте автоматические замечания как список для проверки, а не как сертификат достоверности.
10. **Отчёты и экспорт** — регулярно сохраняйте JSON-копию, XLSX и CSV; сводку можно распечатать в PDF.

## Хранение и безопасность

- Данные хранятся в IndexedDB браузера для конкретного origin (сочетания протокола, домена и порта) на этом компьютере. `http://localhost:5173`, `http://127.0.0.1:5173` и production-домен — разные хранилища; используйте один и тот же адрес и переносите данные через JSON backup. Аккаунта, сервера и облачной синхронизации нет.
- Очистка данных сайта/браузера может удалить проект. JSON-экспорт — обязательная резервная копия.
- Не храните персональные, медицинские, клиентские, финансовые, коммерческие тайны, пароли и иные чувствительные сведения.
- Встроенные промпты не подключают AI автоматически. Они предназначены для копирования во внешний AI-сервис; перед отправкой туда материалов проверьте правила вашей компании и удалите чувствительные данные.
- Командного доступа, разграничения прав, совместного редактирования и серверного журнала аудита в V1 нет. Для команды используйте утверждённые корпоративные хранилища и процессы доступа.

## Ограничения качества

Автоматическая проверка выявляет часть пустых полей, нарушенных связей и просроченных дат. Она не понимает, истинно ли содержание документа, действительно ли процесс соответствует практике и достаточно ли безопасен AI-ответ. Эти решения принимает ответственный человек по первичным источникам.

## Проверка безопасности

См. `SECURITY-REVIEW.md`. В V1 нет шифрования локальной базы данных и управления доступом; используйте только обезличенные или учебные данные. Не храните чувствительную информацию.

## Дополнительные меры защиты

- Приложение блокирует редактор до завершения чтения IndexedDB и проверки структуры. Если чтение локального проекта завершается ошибкой, показывается блокирующее сообщение, редактор и автосохранение остаются отключены.
- Перед ручным сбросом проекта предлагается скачать JSON-резервную копию.
- Перед открытием учебного примера также предлагается скачать резервную копию.
- CSV-экспорт откладывает освобождение временного URL, чтобы браузер успел начать загрузку.
- CSV-ячейки, начинающиеся с потенциальных маркеров формул (=, +, -, @), экранируются перед открытием в табличных редакторах.
- При удалении связанных записей зависимые записи сохраняются, а ссылки очищаются; действие попадает в локальный журнал.

### Дополнительная защита импорта

Импортируемый JSON ограничен 5 МБ. До миграции и применения проверяется структура всего объекта: запрещены опасные ключи прототипа, глубина вложенности более 64 уровней и объектные графы более 100 000 значений. Это снижает риск некорректных или специально сформированных резервных копий, но не заменяет антивирусную проверку устройства и аудит браузерных зависимостей.

**Data safety note:** if the active-project pointer is missing while project records remain, the app stops instead of creating a fresh project. A browser leave warning appears while a save is pending or after a save failure. These behaviors still require browser-level verification.


## Управленческая диагностика

Отчёт показывает сигналы только по явно внесённым данным: незакреплённые процессы, источники без владельцев, несколько источников типа «Знание сотрудника» у одного владельца, открытые проблемы и документы с просроченной проверкой. Одна запись знания сотрудника не считается доказательством концентрации. Критические и высокоприоритетные процессы считаются отдельно по явно выбранной руководителем критичности. Все выводы требуют проверки с владельцами процессов; пустые поля могут означать отсутствие данных, а не отсутствие проблемы.

### Воспроизводимость сборки

В репозитории зафиксированы версии зависимостей и присутствует `package-lock.json`. CI использует `npm ci`, чтобы устанавливать зависимости по lockfile. Перед релизом нужно повторить CI на актуальном коммите и проверить фактический результат сборки; не обновляйте зависимости до `latest` без отдельной проверки совместимости.
### Автоматизированная проверка релиза в Windows

В папке проекта откройте PowerShell и выполните `powershell -ExecutionPolicy Bypass -File .\scripts\verify-release.ps1`. Скрипт проверит Node.js (нужна версия 22.6.0 или новее) и доступ к npm registry, создаст `package-lock.json` на основе опубликованных версий, выполнит чистую установку через `npm ci`, установит Chromium для Playwright, запустит `npm audit`, production build, unit-тесты и E2E. Полный вывод сохранится в `release-verification.log`. Первый запуск требует доступа к интернету. После успешного запуска сохраните созданный `package-lock.json` вместе с исходниками; дальнейшие установки должны выполняться через `npm ci`.

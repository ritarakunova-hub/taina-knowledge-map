# Публикация TAINA Knowledge Map на GitHub Pages

## Что уже настроено

- GitHub Actions устанавливает зависимости строго по `package-lock.json` (`npm ci`).
- Запускаются 65 модульных тестов.
- Устанавливается Chromium и запускаются 8 браузерных сценариев.
- Собирается production-версия.
- `base` автоматически учитывает имя GitHub-репозитория.
- Готовая папка `dist` публикуется на GitHub Pages.

## Что нужно сделать один раз

1. Создать на GitHub новый **Public** репозиторий с именем `taina-knowledge-map`.
2. Загрузить в него содержимое этой папки проекта (не саму папку-обёртку и не `node_modules`).
3. Убедиться, что основная ветка называется `main`.
4. Открыть репозиторий → **Settings → Pages**.
5. В разделе **Build and deployment** выбрать **GitHub Actions**.
6. Открыть вкладку **Actions**. Дождаться завершения workflow `Build, test and deploy TAINA Knowledge Map`.
7. После успешного запуска GitHub покажет адрес сайта в окружении `github-pages`. Для репозитория `taina-knowledge-map` адрес будет иметь вид:
   `https://<имя-пользователя>.github.io/taina-knowledge-map/`

## Как обновлять приложение

После загрузки изменений в ветку `main` тесты, сборка и публикация запускаются автоматически.

## Важно о данных

Приложение хранит данные локально в браузере (IndexedDB). Публикация сайта не создаёт общую базу между пользователями и устройствами. Данные конкретного браузера не синхронизируются с другими пользователями. Для переноса используйте JSON backup. Для пилота используйте только синтетические или обезличенные данные.

## Если workflow падает

Откройте **Actions → последний запуск → первый красный шаг** и сохраните текст ошибки. Не отключайте тесты ради публикации: сначала разберём причину.

## Найденное несоответствие документации

README предлагал открывать `http://localhost:5173`, но Vite dev server и preview привязаны к `127.0.0.1`. Для браузера `localhost` и `127.0.0.1` — разные origins. IndexedDB и Web Locks привязаны к origin, поэтому пользователь мог открыть приложение под другим адресом и увидеть пустое хранилище, хотя данные остались в другом origin. Это риск ошибочного впечатления о потере данных.

**Исправлено:** README теперь требует открывать точный адрес, напечатанный Vite, не менять hostname и предупреждает, что production-домен — отдельное хранилище. Перенос данных — через JSON backup.

## Остаточные риски

1. Production build не проверен в этой среде.
2. Playwright E2E не запускались; описанные сценарии — подготовленные проверки, не доказательство прохождения.
3. Реальная атомарность IndexedDB и блокировка двух вкладок требуют браузерного прогона.
4. Зависимости всё ещё объявлены как `latest`; `package-lock.json` отсутствует. До релиза нужны точные версии, lockfile, `npm ci` и `npm audit`.
5. Данные IndexedDB не зашифрованы; для пилота использовать только синтетические или обезличенные сведения.
6. Управленческий отчёт ранжирует формальные сигналы из заполненной карты; он не вычисляет вероятность инцидента и не оценивает финансовый ущерб.

## Продуктовый вывод

V1 годится как инструмент структурированной диагностики одного процесса на пилоте под сопровождением. Не позиционировать его как корпоративное хранилище, совместную базу знаний, RAG/AI-поиск, защищённую систему или готовую production-платформу.
